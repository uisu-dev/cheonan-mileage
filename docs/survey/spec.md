## 2. 설문별 구성 요약

### 2.1 2026학년도 교육과정 만족도 조사

공통 리커트 5점 (원문 머리칸을 한 줄로 복원):

`매우 그렇다` / `그렇다` / `보통이다` / `그렇지않다` / `전혀 그렇지 않다`

- `그렇지않다`는 원문에 띄어쓰기가 없다. 그대로 쓴다.
- 머리칸은 셀 안에서 줄바꿈되어 있다(`매우`/`그렇다`, `보통`/`이다`, `전혀`/`그렇지 않다`).
- **「학교 선택 (2개 이상)」은 학교자체평가의 선택 지표 구역 제목**이다. 응답자가 문항을 2개 이상 고르는 다중선택이 아니다. 지표 번호 5-9, 5-16은 모두 리커트 필수 문항이다.
- 세 양식 모두 마지막에 같은 서술형 1문항이 있다.  
  `서술형1) 학교 교육과정 운영에서 만족한 점과 개선이 필요하다고 느낀 점을 구체적으로 적어주세요.`
- 안내문 날짜: `2026. 12. 2.` / 서명: `천안중학교장` (실제 실시일이 다르면 사용자 확인 후 교체).
- 안내문에 「모든 내용은 비밀이 보장됩니다」가 있다. 결과 집계 시 개인 식별을 최소화한다.

#### 학생용 (`중학교-학생용`) — 리커트 11 + 서술형 1 = **12문항**

| 영역 | 문항 수 | 지표 |
|---|---|---|
| 교육과정 | 3 | 1-1, 1-2, 1-3 |
| 수업과 생활 교육 | 3 | 2-1, 2-2, 2-3 |
| 학교 운영 | 1 | 3-1 |
| 교육 성과 | 2 | 4-1, 4-3 (4-2 없음) |
| 학교 선택 (2개 이상) | 2 | 5-9, 5-16 |
| 서술형 | 1 | 서술형1 |

접근: 로그인 학생, 마일리지 배너.

#### 학부모용 (`중학교-보호자용`) — 리커트 11 + 서술형 1 = **12문항**

영역·지표 구성은 학생용과 같다(3-2, 3-3, 4-2 없음). **문항 문구는 학생용과 다르다.** 특히 1-2, 1-3, 2-1, 2-2, 2-3, 3-1, 4-3, 5-16. 전문은 JSON을 따른다.

접근: 로그인 없는 학부모 공개 링크.

문서 표기는 「보호자」이나, 화면 카테고리 명칭은 사용자 요청대로 「학부모」로 쓴다.

종이 양식에는 신원 기입란이 없다. 기본은 익명. 학년별 통계가 필요하면 자녀 학년만 선택하게 할지 사용자 확인(모호점 A8).

#### 교사용 (`중학교-교직원용`) — 리커트 14 + 서술형 1 = **15문항**

| 영역 | 문항 수 | 지표 |
|---|---|---|
| 교육과정 | 3 | 1-1, 1-2, 1-3 |
| 수업과 생활 교육 | 3 | 2-1, 2-2, 2-3 |
| 학교 운영 | 3 | 3-1, **3-2**, **3-3** (학생·학부모보다 2문항 많음) |
| 교육 성과 | 3 | 4-1, **4-2**, 4-3 (학생·학부모보다 1문항 많음) |
| 학교 선택 (2개 이상) | 2 | 5-9, 5-16 |
| 서술형 | 1 | 서술형1 |

접근: 로그인한 `teacher` 또는 `admin` 역할, 마일리지 배너. 문서 표기는 「교직원용」이다.

문항 문구는 학생·학부모와 크게 다르다. 반드시 JSON의 교직원용 텍스트를 쓴다.

### 2.2 2027학년도 학생·학부모 참여예산제 조사

문서 제목: **학생·학부모참여 예산편성 의견서**

이 조사는 선택형 만족도가 아니라 **사업 제안 양식**이다.

- 응답 대상: **학생, 학부모만**. 교사(교직원) 응답 칸은 문서에 없다.  
  → 교사는 하단 배너로 **결과 조회·출력·엑셀**만 한다. (추론 I6)
- 교사·학생은 마일리지 배너(로그인). 학부모는 공개 링크(문자 발송용).

#### 안내·주의 문구 (화면에 그대로 둘 것)

문서 원문:

- `※ 제출마감일 : 2024년 12월 27일까지` ← **문서 연도가 2024년이다. 새 마감일을 사용자에게 확인한 뒤 교체한다 (모호점 A1).**
- `▪ 학생들의 의견을 수렴하여 학생자치회에서 제출 가능합니다.`
- `▪ 학생, 학부모의 입장에서 '학교예산이 사용되었으면 하고 바라는 사업을 중심'으로 작성하시면 됩니다.`
- `▪ 정확한 산출내역이나 사업금액을 알기 어려운 경우에는 사업명만 적어 주시고 간단하게 설명을 적어 주셔도 됩니다.(예시 참조)`
- `▪ 제출하신 예산편성 의견은 예산조정위원회의 조정 및 학교운영위원회의 심의 과정에서 반영되지 않거나, 증감될 수 있음을 알려드립니다.`
- `▪ 예산편성 요구서 작성 및 학교예산 운영 전반에 관한 문의사항은 교무실(☎041-563-0242)로 전화주시면 성실히 답해 드리겠습니다.`
- 표 아래: `※ 예산요구액 등 기재가 어려우시면 사업명만 간단히 적으셔도 됩니다`

#### 신원 칸

문서 상단: `제안자 성명 : (연락처: )  자녀( 학년  반)  이름:`

개인정보 수집항목: `학부모(이름, 연락처), 학생(학년, 반, 번호, 이름)`

- **학부모**: 제안자 성명, 연락처, 자녀 학년, 반, 이름. 「번호」는 상단 서식에는 없고 수집항목에만 있다(모호점 A4).
- **학생**: 로그인 학번(5자리 = 학년 1 + 반 2 + 번호 2)과 이름으로 자동 채움. 수정 가능 여부는 자동 채움 후 확인만 하게 해도 된다.

#### 사업 제안 (반복 1~3건)

표 머리: `순` / `사업명` / `사업내용` / `예산요구액` / `요구사유`

문서 예시(제출 데이터가 아님, 화면에 예시로만 표시):

| 순 | 사업명 | 사업내용 | 예산요구액 | 요구사유 |
|---|---|---|---|---|
| 1 | (예시) 우산 거치대 | 교실 출입구 (4군데) 우산 거치대 설치 | 1,000,000원 | 비올 때 젖어서 불편함 |

빈 행이 2, 3번으로 있다. 디지털 폼에서는 예시와 별도로 **최소 1건, 최대 3건**. 한 건을 적으면 **사업명은 필수**, 나머지 칸은 선택.

#### 개인정보 수집·이용 동의 (제출 전 필수)

제목: `개인정보 수집·이용 동의서`  
(문서에는 `수집․이용`처럼 가운뎃점이 섞여 있다. 화면에서는 `수집·이용`으로 통일해도 된다.)

1. 수집이용목적 : 학생·학부모참여 예산편성 의견 수렴  
2. 수집항목 : 학부모(이름, 연락처), 학생(학년, 반, 번호, 이름)  
3. 이용 및 보유기간 : 학생·학부모참여 예산편성 종료 시까지  
4. 동의를 거부할 수 있으며, 동의 거부 시 예산편성 시 반영되지 않을 수 있습니다.

문항: `개인정보 수집·이용 동의` — 단일 선택 `□예` / `□아니요`. **「예」가 아니면 제출 불가.**

추가 안내:

- `※ 만 14세 미만 학생의 경우 보호자(법정대리인)의 동의가 필요합니다.` (처리 방법은 모호점 A5)
- `※ 수집한 개인정보는 정보주체의 동의 없이 수집한 목적 외로 사용하거나 제3자에게 제공되지 않으며 보유 및 이용기간 만료 이후에는 파기합니다.`

### 3.1 학생 (로그인)

- 위치: `#studentPage` 상단, 기존 배너들과 같은 자리.

### 3.2 교사 (로그인, role=`teacher` 또는 `admin`)

  현재 교사 페이지(`#teacherPage`) 탭이 끝난 뒤, 기존 프로모 배너 3개(교육활동 계획 / 생활규정 챗봇 / 정보게시판)와 「개발 사이트 모음」 타일(`#teacherAppGrid`)이 있다. **이 블록의 가장 아래**(타일 그리드 다음)에 결과 배너를 둔다.
- 결과 화면에서 해야 할 일:
  - 두 조사 각각, **교사 / 학생 / 학부모** 구분 통계
  - 리커트: 보기별 인원·비율 막대(기존 `getSurveyStats` 스타일을 발전)
  - 서술형·사업 제안: 목록
  - **인쇄** (`window.print` 또는 인쇄용 창 — 출석/1인1역 인쇄 패턴이 이미 있음)
  - **엑셀 다운로드** (UTF-8 BOM CSV도 Excel에서 열리지만, 가능하면 `.xlsx`. 이스포츠·1인1역은 현재 CSV)
- 교육과정 결과는 비밀 보장에 맞게 집계 위주. 참여예산제는 제안자 정보(학부모 성명·연락처, 학생 학년반번호 이름)가 결과·엑셀에 필요하다.

### 3.3 학부모 (비로그인 공개 링크)

- 문자 발송용 URL을 설문별로 만든다. 예:  
  `https://cheonan-mileage.vercel.app/survey/curriculum-parent`  
  `https://cheonan-mileage.vercel.app/survey/budget-parent`  
  (`vercel.json`은 지금 `/api/`가 아닌 모든 경로를 `/public/index.html`로 보낸다. 공개 페이지를 `index.html`의 라우트/쿼리로 구현하거나, 별도 정적 HTML을 추가하고 rewrite를 조정한다.)
- 로그인 UI를 요구하지 않는다. 마일리지 기능은 보이지 않게 한다.
- 교육과정은 보호자용 문항, 참여예산제는 학부모 신원 + 제안 + 동의.
- 스팸·중복 대책은 가볍게라도 둔다(동일 연락처 재제출 제한 등). 과도한 인증(문자 OTP 등)은 요청에 없다.

## 4. 저장소 구조 메모 (읽기 전용 조사, 2026-11-13 커밋 `4ce3d41`)

**중요: 이 저장소는 Next.js가 아니다.** 단일 페이지 `public/index.html`(약 4484행, Bootstrap 기반) + Vercel Serverless `api/*.js` + Supabase JS 클라이언트이다.

```
package.json          # "dev": "vercel dev", 의존성 @supabase/supabase-js만
vercel.json           # /api/ 제외 전 경로를 /public/index.html 로 rewrite
public/index.html     # 로그인·교사·학생 UI 전부
api/*.js              # auth, survey, get-data, points, …
lib/supabase.js       # SERVICE_KEY로 서버 클라이언트, CORS 허용
sql/schema.sql        # 최초 스키마
sql/*.sql             # 기능별 추가 마이그레이션 (에디터에서 수동 실행)
```

### 4.1 인증·역할

- `api/auth.js` `action=login`: `users` 테이블에서 `id`+`password` 대조. 세션 토큰·쿠키 없음. 클라이언트가 `{id, name, role, points, …}`를 들고 이후 API에 `userId`/`role`을 보낸다.
- `users.role`: `student` | `teacher` | `admin` (기본값 `student`). `admin`은 교사 화면과 같다 (`isTeacher = role === 'teacher' || role === 'admin'`).
- **학부모 역할은 없다.** 학부모 공개 링크는 비로그인 전용 API가 필요하다.
- 학생 학번은 숫자 5자리. `get-data.js` 기준 앞 1자리=학년, 다음 2자리=반, 마지막 2자리=번호. 예: `10327` → 1학년 3반 27번.
- 교사 화면에 「선생님」으로 표시. 문서의 「교직원용」은 teacher+admin에 매핑.

### 4.2 배너 위치

- **교사 하단 프로모 배너**: `public/index.html` 약 342–431행. 클래스 `promo-banner`. 그 다음 `#teacherAppGrid`. `#teacherPage`는 434행에서 닫힌다.
- **학생 상단 배너/버튼**: 약 445–448행 (돌림판, 인권 생활시, 이스포츠, 상점 우수자 설문).

결과 배너는 교사 페이지 맨 아래, 참여 배너는 학생 상단(+ 교사 참여용)에 기존 패턴을 따른다.

### 4.3 기존 설문 시스템 — 재사용 시 주의

이미 일반 설문이 있다.

- 테이블 `surveys` (`id`, `title`, `questions JSONB`, `status` …)  
  `status`: `O` 공개, `C` 마감, `M` 대상자 전용(상점 우수자).
- 테이블 `survey_logs` (`vote_id`, `student_id`, `answer JSONB`, 이후 `photo_url`/`video_url` 컬럼이 코드 fallback으로 추가됨).
- 문항 형식: `{ q, type: 'radio'|'text', opts: [] }`. 리커트·다중선택 타입은 없다. 리커트는 `radio`+5개 `opts`로 표현 가능하다.
- 교사 설문 탭(`#surveyTab` / `#teacherSurveyList`)에서 결과 HTML(`getSurveyStats`)을 보여 준다. **인쇄·엑셀 버튼은 설문에 없다.**
- `api/survey.js` `action=vote`:
  - `(vote_id, student_id)` 중복 참여 거부
  - **참여 시 100P 지급** (징계 중이면 0점)
  - 로그인 학생을 전제로 한다.

**이번 공식 조사는 기존 `vote`를 그대로 쓰면 안 된다.** 100P가 나가기 때문이다. 별도 action/API(그리고 필요하면 별도 테이블)를 만든다. 기존 일반 설문·상점 우수자·통일조사 복권은 깨지지 않게 둔다.

### 4.4 스키마·마이그레이션 방식

- 최초 스키마는 `sql/schema.sql`. 이후 기능은 `sql/esports.sql`, `sql/human_rights_poems.sql`처럼 **새 SQL 파일을 추가**하고 Supabase SQL Editor에서 실행하는 방식이다.
- RLS는 비활성. API는 `SUPABASE_SERVICE_KEY`만 사용.
- 코드가 예전 컬럼에 맞춰 insert fallback을 하는 경우가 있다. 이번 기능은 `sql/`에 idempotent 마이그레이션을 명확히 넣고, 필요한 컬럼을 전제로 구현하는 편이 낫다.

권장 스키마(구현자가 다듬어도 됨):

- 공식 조사 정의와 문항은 코드+JSON 또는 DB에 고정 시드.
- 응답 테이블은 `survey_logs`를 확장하거나, 예: `official_survey_responses`  
  (`survey_id`, `respondent_type` student|teacher|parent, `respondent_key`, `grade`/`class`/`number`, `answers JSONB`, `meta JSONB`, `created_at`).
- 참여예산제 학부모 연락처 등 개인정보는 목적 외 사용 금지, 종료 후 파기 안내를 지킨다.
- 학생은 조사별로 1회, 학부모는 연락처(또는 자녀+연락처) 기준 1회를 권장.
- 교육과정 서술형 저장 시 결과 화면 기본값은 비식별(모호점 A7).

### 4.5 기타 구현 주의

- 프론트는 `public/index.html` 한 파일에 거의 다 들어 있다. 공식 설문 UI가 커지면 별도 `public/official-survey.html` + rewrite가 유지보수에 유리할 수 있으나, 기존 패턴에 맞춰 같은 파일에 넣어도 된다.
- 마일리지·출석 등 기존 기능, 모바일 글자 크기(`.promo-banner-title` 등)를 깨지 않는다.
- 배포는 Vercel. 스키마 변경은 Supabase에 별도 적용해야 하며, 코드만 푸시해서는 테이블이 생기지 않는다. `sql/` 파일과 적용 방법을 명시한다.

## 5. 추론 (구현에 반영, 문서에 명시되지 않은 부분)

1. `.hwp` = 교육과정 만족도 3종, `.hwpx` = 참여예산 의견서.
2. 「보호자」= 학부모 카테고리, 「교직원」= 마일리지의 teacher/admin.
3. 「학교 선택 (2개 이상)」은 다중선택이 아니라 선택 지표 구역이다.

5. 참여예산제 응답은 학생·학부모만. 교사는 결과만 본다.
6. 리커트는 전부 필수. 서술형은 문서에 필수 표시가 없으나 필수로 권장(A3).
7. 참여예산 제안은 1~3건, 건당 사업명 필수.
8. 기존 설문 `vote`(100P)를 쓰지 않는다.
9. 교육과정은 익명성 강조, 참여예산제는 실명 의견서.
10. 학부모는 설문별 공개 링크.

## 7. 구현자가 하면 안 되는 일

- 저장소에 이 스펙 작업 중 임의 push, 강제 push, 시크릿 커밋.
- 기존 일반 설문에 100P가 나가는 `vote`로 공식 조사를 처리하기.
- 학생용 문항을 학부모·교사에게 그대로 쓰기 (문구·문항 수가 다름).

- Next.js로 프로젝트를 재작성하기. 현재 스택(정적 HTML + `api/*.js` + Supabase)을 유지한다.
